# 決定事項と検討事項

更新日：2026年11月18日。ゲーム仕様の詳しい根拠は[企画書](flight-booker-game-proposal.md)を参照します。この一覧は企画書の代わりに別のルールを定めるものではありません。ただし、企画書の作成後にユーザーが決めた変更は、この一覧に「企画書から変更」と明記して記録します。

## 基本仕様

| 項目             | 採用している内容                                                                                                                                                                                                                                                                                                                                                         |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 実装方式         | PCブラウザ向けのWebゲーム                                                                                                                                                                                                                                                                                                                                                |
| 表示する情報     | 人物・航空会社・予約サイト・便・決済情報は架空。空港と都市は実在の名前を使う（企画書から変更。2026年11月17日）                                                                                                                                                                                                                                                           |
| 路線             | 国際線（企画書から変更。2026年11月17日）。時刻は各空港の現地時間で表示する                                                                                                                                                                                                                                                                                               |
| 実在の空港       | 名前とコードだけを使い、ロゴやシンボルマークは使わない。公認や提携に見える表現をしない                                                                                                                                                                                                                                                                                   |
| パスポート       | 発行国は架空の「NOVA REPUBLIC」のまま。実在の国のパスポートのデザインはまねない                                                                                                                                                                                                                                                                                          |
| 画面             | 左80%が架空PC。右20%の上半分がメモ、下半分がパスポート・カード                                                                                                                                                                                                                                                                                                           |
| 画面の見た目     | 机の上を見下ろす構図。架空PCは、机に平置きしたタブレットとして描く                                                                                                                                                                                                                                                                                                       |
| 資料             | 同じラウンドでは全員共通。ラウンドごとに変更                                                                                                                                                                                                                                                                                                                             |
| サイト           | 比較サイト1種類と、特性の異なる予約サイト3種類から開始                                                                                                                                                                                                                                                                                                                   |
| 在庫             | 全サイトで共通。在庫への反映と二重購入防止を市場処理に集約                                                                                                                                                                                                                                                                                                               |
| 確保             | 1人で何枠でも可能。追加の枠ごとに入力・手続きが必要                                                                                                                                                                                                                                                                                                                      |
| 確保の帰属       | サイト・手続き・価格にひも付く。他サイトの価格へ流用しない                                                                                                                                                                                                                                                                                                               |
| 購入             | 1人1ラウンド1件。成功時に本人の別の未購入枠を解放                                                                                                                                                                                                                                                                                                                        |
| コピーと貼り付け | 禁止（2026年11月18日に決定）。資料の文字は選べず、タブレットと資料の中ではコピー・切り取り・貼り付け・文字のドラッグ＆ドロップを止める。入力欄はブラウザの自動入力も切る。ゲーム内ブラウザのアドレスバーだけは、URLを別のタブへ写せるように止めない。資料を見ながら打つ手間が競争の中心で、確保枠の抱え込みを入力の手間で抑える前提でもあるため                          |
| 誤入力           | 予約を通し、入力ミスも条件違反もラウンド終了時に判定                                                                                                                                                                                                                                                                                                                     |
| 減点             | 違反の重さで3段階（案C。2026年11月17日に決定、同日のプレイテストで条件違反の扱いを変更）。出発地・目的地・出発日の違いは時間切れと同じ扱い。それ以外の条件違反は、集計金額をラウンド最高値にし、同額なら正しい便の予約を上にする（条件違反が正しい予約より有利にならないため）。入力ミスは、ラウンド最高値に対する割合を集計金額に足す。重なっても時間切れより悪くしない |
| 試合             | 4ラウンド。基本は合計金額の小さい順、同額なら合計予約タイム                                                                                                                                                                                                                                                                                                              |
| 未予約           | 締切までに予約できなければ、ラウンド最高値（条件を満たす便の価格のうち最も高い額）で購入した扱い（2026年11月17日に決定）                                                                                                                                                                                                                                                 |
| 早めの締切       | 参加者の75%が予約した時点で、ラウンドを締め切る（2026年11月17日に決定）。間に合わなかった人は未予約として、ラウンド最高値と制限時間で集計する                                                                                                                                                                                                                            |

## 開発の進め方で決めたこと

| 項目     | 採用している内容                                                   |
| -------- | ------------------------------------------------------------------ |

## 試作用の仮案

以下は正式な調整値ではありません。初期値として実装する場合は、設定で変更できるようにします。

| 項目                     | 仮案                                                                                                                                                                                                                                                                                                    |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 初期人数                 | 人間1人＋NPC9人                                                                                                                                                                                                                                                                                         |
| ラウンド制限時間         | 300秒（企画書の180秒から変更。2026年11月17日）                                                                                                                                                                                                                                                          |
| 開始カウント             | 10秒                                                                                                                                                                                                                                                                                                    |
| 比較検索                 | 4〜6秒（企画書の20〜30秒から変更。2026年11月17日）                                                                                                                                                                                                                                                      |
| 未予約への追加ペナルティ | まず0円。最高値の定義もシナリオとして明示                                                                                                                                                                                                                                                               |
| サイト2の確保の段階      | 搭乗者情報の画面で「決済へ進む」を押した時点（企画書の仮案のまま）                                                                                                                                                                                                                                      |
| 予約フォームの空欄       | 空欄の項目があると先へ進めない。形式や正誤は判定しない                                                                                                                                                                                                                                                  |
| 確保中のタブを閉じた場合 | 確保は残る。本人が購入するか、締切で解放される                                                                                                                                                                                                                                                          |
| サイト3の価格            | 閲覧人数÷参加人数が0%で下限、50%以上で上限。その間は比例し、500円単位に丸める                                                                                                                                                                                                                           |
| サイト3の価格帯          | 下の価格帯の販売枠（指定がなければサイト1と同じ数）が売り切れると、価格の範囲を1.2倍した上の価格帯に上がる（2026年11月18日に決定）。ラウンド最高値は、上の価格帯の上限も含めて決める                                                                                                                    |
| サイト1の売り切れ        | 確定の時点で最安料金の販売枠が尽きていたら、ポップアップで「売り切れました」と知らせる（2026年11月18日に決定）                                                                                                                                                                                          |
| 検索結果の価格           | 検索が終わった時点の市場の価格と空席で作り、その後は変えない。売り切れたサイトは「売り切れ」、満席の便は「満席」と出す。再検索すると新しい価格になる                                                                                                                                                    |
| 検索のURL                | 検索すると、比較サイトのURLが検索条件入りに変わる。アドレスバーは書き換えられ、URLを入れてEnterでそのページを開く。検索結果のURLなら、その条件で検索し直す（2026年11月18日に決定）。知らないURLは「ページが見つかりません」                                                                             |
| 便の自動生成             | 手で書いた便に、自動生成の便を足す（2026年11月18日に決定）。正しい区間・日付には8便（半分は条件を満たし、残りは条件を1つだけ外した安いわな）。同じ都市どうしでない全区間の、出発日の前日・当日・翌日には3便ずつ作り、検索条件を間違えても候補が出るようにする                                           |
| 直行便と乗継便           | 直行便は高くて速い（距離の標準価格の1.08〜1.38倍）。乗継便は安い（0.66〜0.92倍）が、乗継の待ち時間（1〜4時間）の分だけ長い。乗継の空港は、出発地・目的地と同じ都市の空港や、1.7倍を超える遠回りになる空港を使わない                                                                                     |
| NPCの候補選び            | 検索結果で売り切れ・満席と出ている便とサイトの組み合わせは選ばない（人間も検索し直せば見える）                                                                                                                                                                                                          |
| 条件の種類               | 出発時刻・到着期限・手荷物・運航会社・到着ターミナル・席の位置に、予算・直行便のみ・乗継の空港・所要時間の上限を足した（2026年11月18日に決定）。1ラウンドの条件は5〜6個で、ラウンドごとに組み合わせを変える。予算と席は予約で、ほかは便で判定する。予算を超える予約も条件違反（最高値で集計）           |
| ラウンドごとの条件       | 1：出発時刻・到着期限・手荷物・運航会社・所要時間5時間以内。2：出発時刻・到着期限・手荷物・運航会社・席（窓側か通路側）・予算28,000円。3：到着期限・手荷物・運航会社・到着ターミナル・席（窓側）・乗継は台北（桃園）経由のみ。4：出発時刻・到着期限・運航会社・到着ターミナル・席（通路側）・直行便のみ |
| 条件メモの文字の大きさ   | 行が多いラウンドでは、全部が見えるように文字と罫線を小さくする                                                                                                                                                                                                                                          |
| NPCの行動                | 4つの型（サイト1に急ぐ、サイト2で確保、サイト3の値下がり待ち、確保を保険にサイト1を狙う）を番号順に割り当てる。搭乗者情報の入力72〜88秒、決済36〜47秒、候補を決める時間4〜8秒、速さ0.92〜1.1倍（プレイテストで遅くした。最速のNPCが約120秒で予約する）                                                  |
| 入力ミスの判定           | 大文字・小文字、全角・半角、空白、日付や番号の区切りの違いは誤りにしない。国籍は国コードでもよい                                                                                                                                                                                                        |
| NPCの入力                | 1ラウンドごとに、NPCの20%がパスポートかカードの1項目を打ち間違え、15%が条件を1つ見落として便を選ぶ。出発地・目的地・出発日は見落とさない。人間と同じ判定と減点にかける                                                                                                                                  |
| 減点の割合               | 本人確認の入力ミス1つにつき最高値の10%、カードの入力ミスは5%。100円単位に丸める                                                                                                                                                                                                                         |
| 4ラウンドの出題          | 羽田→台北（松山）、羽田→ソウル（金浦）、成田→香港、羽田→台北（桃園）。人物・便・価格の倍率・販売枠は試作用                                                                                                                                                                                              |
| 結果の表示時間           | ローカル版は自動で進めず、ボタンで次へ進む（企画書の仮案の20秒は使わない）                                                                                                                                                                                                                              |
| サイト3の閲覧人数        | 同一人物の複数タブは1人として数える                                                                                                                                                                                                                                                                     |
| 同額・同タイム           | 完全一致なら同順位                                                                                                                                                                                                                                                                                      |
| 価格帯と距離             | 基本料金＋距離×単価を標準とし、便ごとの倍率と丸めで3サイトの価格を決める。距離は空港の緯度・経度から求める大円距離                                                                                                                                                                                      |
| 座席表                   | 座席指定を設ける（2026年11月18日に決定）。どの便もエコノミー席の一区画（21〜30列、A〜F の3-3配列）を見せ、便の座席数だけが空席、残りは一般の乗客が予約済み。空席は窓側・通路側・真ん中に偏らないように便の番号から決める                                                                                |
| 座席の手順               | 便の確認 → 座席 → 搭乗者情報 → 決済。席を選んだだけでは確保しない（サイト2は「決済へ進む」で、選んだ席を確保）。指定しない「おまかせ」も選べ、確定時に空いている席を割り当てる。選んだ席だけが埋まったら、入力を残したまま座席の画面へ戻す                                                              |
| 席の条件                 | 条件メモに席の位置の条件を入れる（2026年11月18日に決定）。合わない席を買うと条件違反（最高値で集計）。おまかせで割り当てられた席も同じく判定する。ラウンド1は条件なし、2は窓側か通路側、3は窓側、4は通路側                                                                                              |
| 席の条件と座席数         | 条件を満たす便の、条件に合う席が参加者の人数以上になるようにする。ラウンド2〜4の条件を満たす便は座席数を増やし、条件に合う席を各ラウンド14席にした                                                                                                                                                      |
| NPCの席選び              | 席の条件があれば、空いている席のうち条件に合う席を選ぶ（2〜4秒）。選んだ席が埋まっていたら、条件に合う別の席を選び直して同じ手続きを続ける。条件に合う席が空いていない便は候補にしない。席の条件も見落とすことがある                                                                                    |

## 実装前に詰める項目

| 項目                     | 決める内容                                     | 決める時期           |
| ------------------------ | ---------------------------------------------- | -------------------- |
| 未入力・形式不正         | 空欄や極端な形式不正をどこまで通すか           | 予約フォームの実装前 |
| 確保フェーズ             | サイト2のどの入力・画面遷移で確保するか        | 確保処理の実装前     |
| 枠数と価格変動           | 人数に対する最安枠、適合便の供給、変動幅       | NPC導入後の試作      |
| 時間切れの追加ペナルティ | ラウンド最高値に加える額（今は0円）            | プレイテストの後     |
| オンライン               | 通信、切断・復帰、遅延、表示価格と確定価格の差 | オンライン版の設計時 |

確保数やタブ数に固定の上限を置いて、未検証の問題を解決したことにしません。入力の手間で大量確保が抑えられるかは、プレイテストで確認する仮説です。

購入額・実タイム・違反内容・減点は、別々の値として残します。全違反を一律の最高値扱いにしたり、合計金額とは別の順位点方式に変えたりしません。
